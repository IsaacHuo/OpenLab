# OpenLab 工作区布局与交互

本规范将[确认后的视觉基准](README.md)映射到现有研究工作区。功能语义继续遵循 [docs/workspace.md](../../docs/workspace.md) 与现有 API；此次设计不改变模型调用、研究确认、权限、持久化或事件流协议。

## 布局与导航

在 1440 × 1024 的桌面基准视口中，侧栏约 256px，成果栏默认 400px，中间聊天占据剩余空间。顶部工具栏高 72px，内容内边距 24px。分隔线计入实际布局；尺寸以 [tokens.css](tokens.css)为准，不拉伸参考图填满屏幕。

| 区域 | 内容与职责 |
| --- | --- |
| 左侧导航 | OpenLab 文字字标、新对话、项目、当前项目内的对话；底部技能与工具、设置、本地状态 |
| 中央聊天 | 项目与对话定位、用户消息、助手回复、研究计划、简洁运行摘要、成果入口、输入区 |
| 右侧成果 | 报告、来源、附件标签；修订选择、报告阅读、引用定位、来源详情、下载 |

保留项目与对话的实际父子关系。当前没有项目时提供清晰的新建项目入口；已有项目时“新对话”调用现有创建对话逻辑。运行历史通过对话上下文的次级入口访问，不与项目和对话平铺争夺导航主位。

聊天和报告分别滚动，输入区位于聊天列底部，不覆盖消息末尾。不能把用户问题、研究过程、报告正文重复铺满三个区域。对话主体保留舒适留白，不用重复欢迎语、说明段落或空卡片填空。

## 聊天输入

输入框是主操作区。外容器使用 `24px` 圆角、1px 中性边框和 16px 内边距，默认最小高度 120px。正文输入自动增长，达到 240px 后内部滚动；多行内容不压住下方工具栏。

- 占位文案为“继续提问，或补充研究方向…”，空会话可用“描述你的研究问题…”。可访问标签独立存在，不依赖占位文案。
- 下方工具栏左侧是添加附件、研究模式和模型；技能在研究模式菜单中选择并显示当前值，不再长期并排暴露三个原生选择框。
- 右侧为发送图标按钮，桌面 40 × 40px；可访问名称准确表达“生成研究计划”等实际动作，不把发送图标解释为已获准自动执行研究。
- Enter 提交，Shift+Enter 换行；中文输入法 composition 期间 Enter 只确认候选字，不提交。
- **输入框外下方不渲染常驻说明、标语或替代提示。** 底部只保留必要的布局留白，不保留被删除文案的元素或固定高度容器。
- 附件条目放在输入框内，展示文件名并可打开预览；保留现有格式、体积限制和上传逻辑。当前服务没有附件删除接口，不提供虚假的移除操作。
- 未配置模型、草稿为空、项目已归档、断开连接或已有活跃运行时，保留实际发送限制。禁用原因放在相关配置或上下文中，不能只藏在无法聚焦的禁用按钮 Tooltip 内。
- 当前对话已有活跃运行时，新问题继续保留为未发送草稿。确需说明时使用该运行的状态区域，不在输入框下方恢复常驻小字。

移除的是固定帮助文案，不是决定所需的信息。模型菜单和设置中保留模型使用、已知能力及预算事实，重要成本说明在选择模型或生成计划的相关上下文可见；计划确认卡片保留研究范围，权限卡片保留具体授权范围。不得只用 Tooltip 承载重要决定信息，也不新增每次发送都要重复确认的流程。

## 对话与执行

用户消息使用轻灰消息底，助手回复直接排在白色聊天面上。Markdown 正文、引用和工具结果沿用真实数据渲染，不另建模拟聊天记录。

| 当前状态 | 呈现方式 |
| --- | --- |
| 初次使用或空会话 | 主动作是输入研究问题；简短标题即可，配置缺失时提供对应设置入口 |
| 等待计划确认 | 在聊天中展示计划、方法、范围与明确确认操作，不能用“已开始研究”掩盖待确认状态 |
| 正在执行 | 单条简洁摘要显示实际阶段；可展开步骤；保留取消入口，不虚构百分比 |
| 等待回答或授权 | 在对应消息位置展示既有问题或权限卡，显式提供允许、拒绝或回答操作 |
| 执行完成 | 摘要默认折叠，报告作为可打开成果；“完成”不等于论文论点已核实 |
| 失败、取消、中断 | 保留真实状态、已保存内容与明确重试入口；重试仍使用既有新运行逻辑 |
| 连接断开 | 将连接状态与运行状态分开，不能因断流显示成功或自动重新发起任务 |

只展示用户可理解的实际阶段、工具活动与证据记录。原始 JSON、哈希、调试输出留在详情内；来源记录和生成步骤仍可从报告追溯。切换旧运行时显示该运行自己的状态及成果。

## 报告与 Artifact 面板

参考图展示的是“已有成果且报告面板展开”的状态，不要求所有场景常驻右栏。已有成果会话恢复用户的展开选择；新会话默认优先给予聊天空间。点击成果条目、成果入口或引用时展开所需内容，用户可关闭面板。

- 标签为“报告”“来源”“附件”，计数来自各自的真实记录。标签切换不清除聊天草稿或改变运行。
- 报告顶部为修订选择与下载；正文按标题、章节、段落、列表排版，不把报告渲染成一组卡片。
- 草稿、已提交修订、旧版及新版提示沿用平台实际语义。旧版不能无提示跳转至新版，示例中的“v1”不定义新的后端版本字段。
- 引用打开对应来源，并保留来源的元数据、全文访问范围、验证程度与局限；从来源和报告可返回实际生成步骤。
- 来源和附件使用轻量列表。长标题换行或提供可访问的完整名称，内容和错误信息不截断。
- 已获取元数据不能呈现为论文结论已验证，检索为空不能显示合成报告假装成功。
- 预览与下载复用现有接口。不因设计稿添加在线编辑、发布、协作或新 Artifact 格式。

成果栏支持现有指针拖动与键盘调宽，范围 300–640px，并优先保证聊天至少 560px。空间不足时折叠导航或改为抽屉，不挤压为窄到不可读的三栏。

## 响应式行为

| 视口宽度 | 默认布局 |
| --- | --- |
| 至少 1440px | 三栏；导航 256px，展开的成果栏 400px，聊天占剩余空间 |
| 1280–1439px | 三栏；导航 224px，展开的成果栏 360px，聊天占剩余空间 |
| 1024–1279px | 导航收为 56px 图标栏；成果栏按剩余空间展开或收起，不能令聊天小于 560px |
| 小于 1024px | 单聊天列；导航和成果分别通过有名称的抽屉打开，关闭后返回触发控件 |

手机输入区横向边距 12px，正文字号保持 16px，外圆角仍为 24px；模式和模型工具栏可换行，不能隐藏当前配置或用 9px 小字硬塞。长报告表格与代码仅在各自容器内横向滚动，不让整个页面横向滚动。移动端考虑安全区和软键盘，输入框不离开可视区。

视口变化、折叠、抽屉切换不得丢失当前项目、对话、运行、修订、来源选择或未发送草稿。

## 实现边界与验收

现有 `web/workspace.tsx` 的选择、草稿和回调是行为参考，`web/conversation.tsx` 继续连接 assistant-ui/AG-UI；`web/style.css` 的旧配色不是视觉参考。可拆出视图组件，但不改后端接口、不引入第二套会话状态、不整体重写项目。

后续实现按布局与导航、输入区、执行呈现、成果面板的顺序分批验证。图中没有展示的设置、技能及错误状态，也应使用同一套令牌与基础组件。

- 使用同一份合成研究记录，对比 1440 × 1024 的已完成状态和本目录参考图，核对层次、比例、正文、输入区和报告。
- 确认输入框外下方没有小字或说明占位；计算样式中的输入框外圆角为 24px。
- 覆盖空会话、长中文与英文、执行中、等待确认、等待授权、失败、断连和长报告。
- 检查 1440、1280、1024、768、390px 下的导航、抽屉、输入区、滚动与引用跳转；验证键盘焦点、Esc、标签与中文输入法提交。
- 回归现有计划确认、权限回答、取消、重试、报告修订、附件和来源到步骤的导航，不调用真实付费模型做视觉验证。
- 代码落地后运行类型检查、构建和受影响的浏览器用例，再对实际页面截图。规范文件或生成稿本身不能替代运行验证。

## 插件化文档工作区修订

2026-10-24 用户批准：默认能力也以插件提供。聊天继续为主入口，文档通过辅助成果栏打开；可进入专注阅读、源码编辑、预览和版本对比。Markdown、LaTeX 编辑器、编译器、PDF 预览器分别注册，支持停用和更换默认提供者。

编辑不覆盖原修订。版本列表区分 Agent 生成与人工编辑，草稿保留由平台负责。报告较长时提供目录；选择段落后可将精确修订与文段加入未发送追问。技术 JSON 留在执行详情，输入框下方仍不添加说明文案。差异、编辑器搜索与 PDF 控件同样遵守中性灰阶。

本次修订扩展原先“只读报告”的边界，其余视觉令牌和已选参考保持有效。接口、草稿、编译器和档案约束见[插件 SDK](../../docs/plugins.md)。

## 滚动条修订

2026-10-24 用户确认：聊天、导航、普通成果列表、输入区和菜单隐藏滚动条；长文弹窗、源码编辑器、并排预览与 PDF 区域需要可拖动定位时，使用 4px 纯黑滑块、透明轨道。所有滚动条均无两端箭头；选择菜单不显示上下滚动箭头。隐藏仅改变呈现，保留滚轮、触控与键盘滚动。
